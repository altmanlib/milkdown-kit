# Markdown 往返规范化

## 背景

编辑器加载 Markdown 后再通过 `getMarkdown()` 导出，输出不一定和输入逐字相同。2026-09-23 基于 Milkdown 7.22.1 逐项测试了常见写法：输入 → 导出 → 再次加载 → 再次导出，确认每一项在第二轮之后都不再变化

## 现状

以下改写只改变书写形式，内容不变，且第二轮起保持稳定：

| 输入 | 导出 |
|---|---|
| `- item` | `* item` |
| `Setext` 加 `======` 下划线 | `# Setext` |
| 行尾两个空格的硬换行 | 行尾 `\` 硬换行 |
| 引用式链接 `[ref][1]` 加定义 | 内联链接 `[ref](url)` |
| 连续多个空行 | 一个空行 |
| 编辑器中的空段落 | `<br />` |
| 插入后未填写链接的图片块 | `![]()` |

以下写法原样保留：`__bold__` / `_em_`、HTML 块、转义字符（例如 `\*`）

图片相关的两个上游缺陷会造成内容丢失，本包已经规避，不属于上表的无损规范化，见 [editor-architecture.md](../design/editor-architecture.md) §2.2 和 §4.4

## 影响与触发条件

- 使用方用字符串比较判断「内容是否改动」时，刚加载的文档可能因为规范化被判为已改动。只有用户实际编辑时才会触发 `onChange` / `update:modelValue`，所以按事件判断不受影响
- 使用方的 Markdown 渲染器不允许 HTML 时，空段落导出的 `<br />` 会显示为文本或被过滤
- 空的图片块导出为 `![]()`，渲染器会显示为一张损坏的图片

## 结论

- 表中的规范化接受上游行为，不做处理
- 列表符号使用 `-` 列为开放项，见 [editor-architecture.md](../design/editor-architecture.md) §9
- `<br />` 和 `![]()` 出现在使用方的实际数据中并造成问题时，再在导出阶段过滤
