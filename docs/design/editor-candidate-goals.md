# 开箱编辑器候选目标

## 1. 目标与范围

在 [editor-architecture.md](editor-architecture.md) 已定方案之上，整理后续可评估的目标，供决定是否进入 [ROADMAP.md](../ROADMAP.md)

| 项 | 结论 |
|---|---|
| 文档性质 | 候选清单；未分配 `Rnn` 前不表示承诺交付 |
| 产品定位 | 预配置好的 Markdown 编辑器：功能组合、中文文案、紧凑主题已预设；使用方提供挂载点和业务回调 |
| 成功标准 | 提升「安装后少量配置即可用」的体感 |
| 本文不写 | 实现方案、工期、API 草案；需要时另开设计文档 |

进入路线图的条件：有明确使用场景或回归风险，并能写出触发条件与最小处理方式

## 2. 已交付

| 项 | 现状 |
|---|---|
| 核心与框架包 | `createEditor()`；Vue / React `MdEditor` |
| 功能面 | `FeatureName` 默认全开：`toolbar`、`block-menu`、`code-block`、`image-block`、`table`、`link-tooltip`、`placeholder`；`cursor`、`list-item` 始终开启 |
| 文案与主题 | 默认 `zh-CN`；紧凑主题与 CSS token；代码高亮跟随亮暗色 |
| 业务注入 | `uploadImage` 等回调由使用方提供 |
| 可靠性 | 图片 Markdown 规避；往返 / 组件 / SSR import / 包产物 / 体积上限检查 |
| 已登记按需项 | R02、R05、R07–R12、R14，见 [ROADMAP.md](../ROADMAP.md) §4 |

公开 API、分层与原则以 [editor-architecture.md](editor-architecture.md) 为准

## 3. 筛选原则

1. **符合开箱定位**：解决接入与编辑摩擦
2. **遵守既有原则**：API 最小化、业务外置、优先复用 Crepe、不丢用户数据
3. **能写清触发条件**：没有场景或回归风险的，只留在本文
4. **最小方案优先**：能用文档、约定或单点覆盖解决的，先走这条路
5. **可回归**：用户可见行为尽量落到测试或金样例

## 4. 候选清单

编号仅用于本文内引用（`C01`…），不是路线图编号

### 4.1 粘贴与导入

| 编号 | 项 | 要解决的摩擦 | 契合 | 备注 |
|---|---|---|---|---|
| C01 | VS Code / Cursor 粘贴 `.md` 进正文 | 从编辑器复制 Markdown 会进代码块 | 高 | 已登记为 R14 |
| C02 | 剪贴板图片走 `uploadImage` | 粘贴图片无法走宿主上传 | 高 | |

## 5. 建议优先评估

| 优先 | 覆盖候选 | 理由 |
|---|---|---|
| 1 | C01–C03、C05 | 粘贴闭环影响第一印象；C01 已是 R14 |
| 2 | C11–C13 | 宿主插入与自定义斜杠最贴合现有原则 |
| 3 | C31–C32、C34–C36 | 把可靠性与接入说明做成可回归资产 |
| 4 | C06–C07、C17、C22 | 块操作、只读、触控补成品感 |
| 5 | C19–C20、C27、C30 | 多为约定与打磨，成本低 |

评估产出应能回答：触发条件、最小方案、是否分配 `Rnn`
